# 仕様書: バックアップ（学習記録・教材）と報告の一覧

学習記録と教材パックのエクスポート、学習記録のインポート、解説の誤りの報告の一覧（`study-cards.md` 10 章）の仕様。
学習記録は端末の中にしかないため、バックアップの手段は必須とする（`docs/RULES.md` 4 章）。
項目ごとに検討し、決まったものから「決定」にする。

| 状態 | 意味 |
|---|---|
| 未着手 | まだ検討していない |
| 検討中 | 論点を洗い出し中 |
| 決定 | この仕様書に従って実装してよい |

## 1. 使う場面

### 決定事項

- 想定する場面は、どれも「別の場所に記録や教材を戻す」ことである。
  - 端末を買い替える・初期化する。教材の zip が手元になくても、端末から書き出しておけば戻せる。
  - ブラウザが保存したデータを消してしまったときに備えて、定期的に控えを取る。
  - 配信先の URL が変わる（`docs/RULES.md` 3 章。オリジンが変わると記録も教材も見えなくなる）。
- 複数の端末で同時に学習して記録を合わせる（同期）は対象にしない。同期が必要になったら、`docs/RULES.md` 3 章のとおり別の機能として検討する。

## 2. エクスポートするもの（3 通りの選び方）

### 決定事項

エクスポートでは、次の 3 通りから選ぶ。

| 選び方 | 書き出すファイル |
|---|---|
| 教材と学習記録 | 選んだ教材パックの zip（パックごとに 1 つ）と、学習記録のファイル（1 つ） |
| 学習記録だけ | 学習記録のファイル（1 つ） |
| 教材だけ | 選んだ教材パックの zip（パックごとに 1 つ） |

- 教材と学習記録は、1 つにまとめず別々のファイルにする。
  - 理由: それぞれ今の取り込み（教材）とインポート（学習記録）でそのまま戻せ、新しいファイルの形式を増やさずに済む。また、1 つにまとめるには教材の zip を丸ごともう一度包むことになり、スマホのメモリを 2 倍使う。
  - 戻す順番はどちらが先でもよい。学習記録はパックと単語の `id` で結び付くため（`docs/ARCHITECTURE.md` 4 章）。
- 教材を含めるときは、書き出すパックを選ぶ（初めは全部選んである。ただしデモ教材は「デモを試す」から取り直せるので、初めは選ばない）。
- 学習記録は、選んだパックによらず、すべてのパックの記録を書き出す。インポートは記録を全部置き換えるため（6 章）、一部のパックだけの記録を書き出すと、戻したときにほかのパックの記録が消えてしまう。
- 前回の選び方と選んだパックは `settings` に保存し、次に開いたときに選んだ状態にする（キーは `exportChoice`。学習記録のファイルには含めない）。初めは「学習記録だけ」（小さく、すぐ終わるため）。前回の後に取り込んだパック（デモ教材を除く）は、選んだ状態にする（控えの取り忘れを防ぐため）。

## 3. 学習記録のファイル

### 含めるもの

- 学習記録のテーブル（`docs/ARCHITECTURE.md` 4 章）の中身を、加工せずにそのまま含める。

| テーブル | 含めるか | 理由 |
|---|---|---|
| `progress` | 含める | 定着度は回答の記録から計算し直せるが、そのまま持てば式を変えた後でも戻した直後の値が変わらない |
| `studySessions` | 含める | 生の記録。ユニット学習に混ぜる単語・復習の単語の判定と、定着度の計算し直しに使う |
| `reports` | 含める | `study-cards.md` 10 章 |
| `settings` | 一部を含める | 下記 |

- `settings` のうち含めるもの: 前回選んだ表面の種類（`face`）、ユニット学習の設定（`unitStudy`）、例文を最初から表示するか（`exampleTextShown`）、最後にテストした日時と範囲（`lastTest:<packId>`）、最後にユニット学習した日時とユニット（`lastUnitStudy:<packId>`）。
- 含めないもの:
  - 途中でやめた学習の状態（`inProgress:<packId>`）。出題の並びは、戻した先の教材と食い違うことがあり、続きから再開できる保証がないため。
  - エクスポートの記録（`lastExport`、`exportChoice`）。端末ごとの値のため。
- 取り込んでいないパックの記録も含める。後でそのパックを同じ `id` で取り込めば、記録が引き継がれる。
- 4 つのテーブルは 1 つの読み取りのトランザクションで読む（別のタブで学習中に書き出しても、定着度と回答の記録が食い違わないように）。

### 形式

- JSON（UTF-8）1 ファイル。人が読める形式で持つ（`docs/RULES.md` 5 章）。圧縮はしない。回答の記録は 10 万件でも数 MB（`docs/ARCHITECTURE.md` 4 章）なので、圧縮しなくても十分小さい。
- ファイル名は `vocab-backup-YYYYMMDD-HHmm.json`（端末の時刻）。

```json
{
  "format": "vocab-pwa-backup",
  "version": 1,
  "exportedAt": 1700000000000,
  "progress": [ { "packId": "…", "itemId": "…", "mastery": 0.6, "lastReviewedAt": 0, "lastReviewedAtByFace": {} } ],
  "studySessions": [ { "id": "…", "packId": "…", "startedAt": 0, "mode": "unit", "face": "…", "itemIds": [], "seconds": [], "ratings": "" } ],
  "reports": [ { "id": "…", "at": 0, "packId": "…", "itemId": "…" } ],
  "settings": [ { "key": "face", "value": "…" } ]
}
```

- `format` はこのアプリのバックアップであることの印、`version` は形式の版。各レコードの形は `src/db/types.ts` の学習記録の型と同じにする。
- 形式を変えるときは `version` を上げ、古い版のファイルも読めるように、読み込むときに新しい形へ移し替える。新しい版のファイル（アプリより新しい `version`）は読み込まない（7 章）。

## 4. 教材パックの zip

### 決定事項

- 端末に保存した教材から、教材パックの形式（`docs/CONTENT_FORMAT.md`）の zip を作り直す。取り込みの画面でそのまま取り込める形にする。
  - `manifest.json`: 取り込んだときの `manifest.json` の内容（`packs` テーブル）。ただし `units` は `units` テーブルから作り直す（`{ id, title }`。名前がないユニットは `id` だけ）。自動で区切ったパックは、取り込んだときの `manifest.json` に `units` がなく、そのままでは `items.json` の `unit` が取り込みの検証を通らないため。
  - `items.json`: `items` テーブルの単語を、パック内の並び順に並べる。どの単語にも、取り込んだときに決まったユニット番号を `unit` に入れる（自動で区切った場合も、同じ区切りで取り込み直せるように）。並び順などアプリが足した項目は入れない。区切りの設定値（`features/studyConfig.ts`）が後で変わっても、同じ区切りで戻る。
  - JSON は整形せずに書く（字下げで大きくなり、取り込みの大きさの上限（`docs/CONTENT_FORMAT.md`）を超えないように）。
  - `audio/`: `audioFiles` テーブルの音声ファイルを、取り込んだときのファイル名のまま入れる。
- 取り込んだ元の zip と、ファイルの中身が 1 バイトまで同じになるとは限らない（JSON の整形や、取り込みで使わなかった項目・ファイルは戻らない）。取り込み直したときに、同じ単語・ユニット・音声になることを保証する。テストで、取り込み → 書き出し → 取り込みで中身が変わらないことを確かめる（ユニットを `manifest.json` で決めたパックと、自動で区切ったパックの両方）。
- ファイル名は `<パックの id>.zip`。ファイル名に使えない文字（`/`・`\`・`:` など）は `_` に置き換える（zip の中の `id` はそのまま）。
- 音声はすでに圧縮された形式なので、zip では圧縮せずに入れる（時間がかからず、大きさもほとんど変わらないため）。
- 大きなパック（取り込める上限は合計 200 MB。`docs/CONTENT_FORMAT.md`）でもスマホで止まらないよう、zip は fflate のストリーミングで音声を 1 ファイルずつ読みながら作り、全体を 2 重にメモリに持たない。
- デモ教材のパックも書き出せる。書き出した zip を取り込むと、ふつうの取り込みとして扱う（デモの版の記録 `demoItemsSha256` は付かない）。
- 書き出した zip には教材の中身が入る。アプリはどこにも送らず、端末の共有の画面に渡すだけで、どこに保存するかは利用者が決める（5 章）。

## 5. エクスポートの操作

### 決定事項

- 設定画面の「バックアップ」に、選び方（2 章の 3 通り）と、教材を含めるときのパックの選択と、「エクスポート」ボタンを置く。
- 操作は 2 段にする。「エクスポート」を押すとファイルを作り、作り終えたら、できたファイルの一覧と、保存のボタンを出す。保存のボタンを押すと、端末の共有の画面（Web Share API の `navigator.share` でファイルを渡す）を開く。保存先（「ファイル」アプリ・クラウドストレージ・AirDrop など）は利用者が選ぶ。外部への送信はアプリからは行わない（`docs/RULES.md` 3 章）。
  - 理由: 共有の画面は、利用者が押した直後でないと開けない（とくに iOS の Safari）。大きな zip を作り終えてから開こうとすると、押してからの時間が切れて開けないため。
  - 保存のボタンは、ファイルごとに 1 つ置く。ファイルが複数あって、まとめて共有できるときは、「まとめて保存」も置く。ブラウザは続けて複数のファイルを保存させると止めることがあり、1 つずつ押せるようにしておくため。
  - 共有の画面でファイルを渡せるかは `navigator.canShare({ files })` で確かめる。渡せないとき（PC のブラウザや、ファイルの種類を断るブラウザ）は、そのファイルをダウンロードとして保存する。
  - 共有の画面を閉じた（キャンセルした。`AbortError`）ときは、何も知らせない。ほかの理由で共有の画面が断ったとき（渡せると判定されても、PC の Safari などで断られることがある）は、ダウンロードに切り替える。ダウンロードもできなかったときは、知らせて、もう一度押せるようにする。
- 教材を含めるときは、作っている間は進み具合（何個目のパックか）を出し、ボタンを押せないようにする。パックは 1 つずつ作る。作り終えたファイルは、画面を離れるまで持っておく。
- 上限に近い大きさのパックを複数選んだときにスマホのメモリが足りるか、大きなファイルを共有の画面に渡せるか（とくに iOS）は、実機で確かめる。足りないときは、選べるパックの数を 1 つにするなど、この仕様を見直す。
- ファイルを作る処理は `features/backup/` に、共有の画面を開く・ダウンロードする処理は画面（`pages/settings/`）に置く（共有とダウンロードは DOM に依存するため。`docs/ARCHITECTURE.md` 3 章）。
- 学習記録が 1 件もないときも、学習記録のファイルは書き出せる（空のファイルになる）。教材を含める選び方で、パックを 1 つも選んでいないときは、ボタンを押せない。
- 学習記録のファイルを保存できたら、そのファイルを作った日時（ファイルの中身の時点）を `settings` に保存する（キーは `lastExport`。9 章で使う）。共有の画面では `navigator.share` が成功で返ったとき、ダウンロードでは保存を始めたときを、保存できたとみなす。キャンセルしたときは保存しない。

## 6. インポートの操作

学習記録のファイルのインポートの操作。教材の zip は、今の取り込みの画面で取り込む（`docs/CONTENT_FORMAT.md`）。

### 決定事項

- 設定画面の「バックアップ」に「学習記録をインポート」ボタンを置き、ファイルを選ぶ。
- **端末の学習記録を、ファイルの中身で置き換える**（合わせない）。
  - 理由: 1 章の場面はどれも「戻す」ことで、置き換えで足りる。合わせる場合、同じ単語の定着度が両方にあるときにどちらを取るか、申告を取り消して短くなった回答の記録（`study-cards.md` 5 章）と元の記録のどちらを取るか、取り消した報告を戻してしまわないか、を決める必要があり、誤ると記録が壊れる。
- 選んだ後、置き換える前に確認の画面を出す。
  - ファイルの中身: エクスポートした日時、学習の回数（`studySessions` の件数）、学習済みの語数（`progress` の件数）、報告の数。パックごとの内訳（取り込み済みのパックはタイトル、取り込んでいないパックは `id` と「教材を取り込むと使えます」の一言）。
  - 端末の今の記録の件数と、「今の記録は消えます。先にエクスポートしてください」の一言と、その場で学習記録をエクスポートするボタン（今の記録が 1 件もなければ、一言とボタンは出さない）。
  - 「置き換える」「やめる」。
- 置き換えは 1 つのトランザクションで行う（途中で失敗したら何も変わらない）。教材のテーブルには触れない。
  - `progress`・`studySessions`・`reports` は、全部消してからファイルの中身を書く。
  - `settings` は、学習記録のファイルに含めるキー（3 章）と、途中でやめた学習（`inProgress:<packId>`。戻した記録と合わなくなるため）だけを消してから書く。端末ごとの値（`lastExport`・`exportChoice`）は残す。
- 置き換えた後、件数を知らせる。
- 学習画面を開いている別のタブがあると、置き換えた後の記録に古い回答を書き戻してしまう。置き換えの後は、ブラウザ標準の BroadcastChannel で、ほかのタブに書き込みをやめて開き直すよう知らせる。受け取ったタブの表示は、DB の更新のとき（`src/db/database.ts` の `DB_OUTDATED_EVENT`）と同じものを使う。DB のバージョンの変更（`versionchange`）は、中身を置き換えただけでは届かないため、それとは別に知らせる。

## 7. 読み込めないファイルの扱い

### 決定事項

- 次のどれかに当たる学習記録のファイルは、**何も変えずに**止め、理由を知らせる（一部だけ読み込むことはしない）。
  - JSON として読めない。大きさが上限（50 MB）を超える。
  - `format` が違う（ほかのファイルを選んだ。教材の zip を選んだときは「教材は取り込みの画面から」と案内する）。
  - `version` がアプリより新しい（「アプリを更新してから読み込んでください」）。
  - レコードの形が違う（必須の項目がない、型が違う、`studySessions` の 3 つの配列の長さが合わない、`ratings` に決まった文字以外がある、など）。
  - 値が決まったもの以外（`mode`・`face`、`lastReviewedAtByFace` のキーが `src/db/types.ts` の値でない）か、範囲の外にある（定着度が 0〜1 の外、`seconds` が 0 以上の整数でない など）。
  - 重複がある（各テーブルの主キー、`reports` の同じパック・単語の報告。報告は 1 つの単語に 1 件の前提で扱うため。`src/db/study.ts` の `toggleReport`）。
  - `settings` の値の形が違う。確かめ方は、今の読み出しの処理（`src/db/settings.ts`、`features/session/unitStudySettings.ts` など）と同じものを使う（二重に作らないため）。ユニット学習の設定は、読み出しと同じく、範囲の外の項目を初期値に直して受け付ける（設定値の範囲を後で狭めても、前に書き出したファイルを断らないように）。
- 知らないキーの `settings` は捨てる（形を確かめられないため）。含めないもの（3 章）がファイルにあっても捨てる。

## 8. 報告の一覧

`study-cards.md` 10 章の「実装時に決める論点」を、ここで決める。

### 決定事項

- **置く画面**: ユニット一覧の画面（パックごと）に「誤りを報告した単語（n 語）」を置き、押すと一覧を開く。報告がなければ出さない。
  - 理由: 報告はパックの中身の誤りなので、パックごとに見るのが自然で、直す人も 1 つのパックごとに作業する。
- **一覧の中身**: 見出し語・ユニットの名前（名前がなければ、ユニット一覧と同じ番号の表示。`pages/units/unitLabel.ts`）・報告した日時を、報告した順に並べる。押すと解説（裏面と同じ表示）を開き、そこで報告を取り消せる。
  - 取り込み直しで消えた単語の報告は、単語の `id` だけを出し、その行に「取り消す」ボタンを置く（解説を開けないため）。
  - 取り込んでいないパックの報告は、どこにも出さずに残しておく。そのパックを同じ `id` で取り込めば一覧に出る。
- **テキストでコピー**: 一覧を 1 行 1 語（`id`・見出し語・ユニット）のテキストにしてコピーするボタンを置く。PC で教材を直すときに使う。
- **メモ**: 当面は付けない。どこがおかしいかは、解説を見直せば分かることが多く、学習中に文字を打つ手間を増やさないため。使いながら必要になったら足す。
- **取り込み直した後**: 自動では消さない。直したかどうかはアプリには分からないため、利用者が一覧から取り消す。

## 9. バックアップを促す表示

### 決定事項

- 設定画面の「バックアップ」に、最後にエクスポートした学習記録が何日の何時の時点のものかを出す（一度もなければ「まだエクスポートしていません」）。
- ホームなどで促す表示（例: 最後のエクスポートから 2 週間たったら知らせる）は、当面は出さない。使いながら検討する。
