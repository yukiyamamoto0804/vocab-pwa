# 教材パックの作り方

自分の単語データを、このアプリに取り込める教材パック（zip）にする手順。
形式の細かい決まりは [CONTENT_FORMAT.md](CONTENT_FORMAT.md) にある。この文書は、その形式でデータを作るときの進め方と注意をまとめたもの。

## 0. はじめに: 権利について

- 手元の教材（市販の単語帳など）を自分で入力して教材パックにするときは、**自分の学習のためだけに使う**（私的使用の範囲にとどめる）。その教材パックは**公開・共有・配布しない**（他人に渡す、Web に置く、公開リポジトリに入れる、など）。単語そのものに権利はなくても、教材の選び方・並び・訳・例文・音声は保護されうる。
- **他の人に配りたい**ときは、オープンなライセンスの材料（例: 単語リストの NGSL〈CC BY-SA 4.0〉、英和辞書の EJDict-hand〈CC0〉）と、自分で作ったもの（例文・自分で録音または合成した音声）だけで作る。材料のライセンスが求める表示は、`manifest.json` の `license`・`attribution` に書く（アプリのユニット一覧の下にある「このパックについて」に表示される）。
- 判断に迷うものは、配らない側に倒す。

## 1. 見本を見る

アプリの「デモを試す」で読み込めるデモ教材（20 語 × 2 ユニット）が、形式の見本になる。元のデータは、リポジトリの `demo/` にある（`manifest.json`・`items.json`・`audio/`）。形式のすべての項目を 1 回以上使っているので、書き方に迷ったら真似できる。

- デモ教材のライセンスは CC BY-SA 4.0。**形式（JSON の構造）を真似るだけなら、ライセンスは引き継がれない。** デモの単語の並び・訳・例文・音声をそのまま使って公開する場合は、CC BY-SA 4.0 にする（詳しくは `demo/README.md`）。

## 2. フォルダを用意する

次の形のフォルダを作る。名前は自由（例: `my-pack`）。

```
my-pack/
├── manifest.json   パックの情報とユニットの一覧
├── items.json      単語の一覧
└── audio/          音声（なくてもよい）
```

- JSON は UTF-8 で保存する（Shift_JIS などは取り込めない）。
- 音声のファイル名は、英数字と `-`・`_`・`.` だけにする（zip にしたときに名前が崩れて、`items.json` の指定と合わなくなることがあるため）。

## 3. manifest.json を書く

最小の例:

```json
{
  "formatVersion": 1,
  "id": "my-pack",
  "title": "自分の単語帳"
}
```

- `id` はパックを見分ける名前。**一度決めたら変えない。** 同じ `id` のパックを取り込むと「更新」になり、学習記録が引き継がれる。
  - 試しに取り込む前に決める。取り込んだパックを削除する機能はまだないので、後から `id` を変えると、古いパックが残り続ける。
  - デモ教材の `id`（`demo-ngsl`）は使わない（デモ専用。デモの `manifest.json` を写したときは、必ず書き換える）。
- ユニット（学習のひとまとまり）を自分で分けたいときは、`units` を書き、`items.json` の各単語に `unit` を付ける。書かなければ、並び順で 20 語ずつ自動で分ける。
- 他の人の材料を使ったときは、`license` と `attribution` を書く。

## 4. items.json を書く

最小の例（1 語）:

```json
[
  {
    "id": "0001",
    "word": "light",
    "senses": [
      {
        "meanings": [{ "pos": "名詞", "meaning": "光、明かり" }],
        "example": "The room was full of light.",
        "exampleTranslation": "部屋は光で満ちていた。"
      }
    ]
  }
]
```

- 単語の `id` は、パックの中で重ならない文字列にする。**一度決めたら変えない**（学習記録はこの `id` で結びつく）。並べ替えや単語の追加をしても、既にある単語の `id` は振り直さない。
- 品詞（`pos`）は、[CONTENT_FORMAT.md](CONTENT_FORMAT.md) の「品詞の一覧」から選ぶ。
- 意味が大きく違う使い方は、`senses` を分ける（3 つまでを推奨。多いとカードの文字が小さくなる）。
- あるとよい項目:
  - `exampleTarget`: 例文の中の見出し語の形（`ran` など）。「日本語 → 解説」の穴埋めに使う。例文に見出し語がそのままの形で出てこない（`ran`・`studies` など）ときは書く。書かないと、その用法は「日本語 → 解説」に出ない。
  - `exampleTranslationTarget`: 例文の訳の中で見出し語にあたる部分。太字になる。
  - `idioms`: イディオムと意味。
- 表計算ソフトで作った表から JSON を作る場合は、スクリプトで変換すると、手で書くより誤りが少ない。

## 5. 音声を用意する（なくてもよい）

音声がない単語・例文は、再生ボタンを押すと、アプリが端末の読み上げの声で読む。ただし、音声を聞いて答える表面（「単語の音声 → 解説」「例文の音声 → 解説」）では、教材の音声がない単語・用法は出題されない。用意する場合:

- **1 語 1 ファイル**なら、`"audio": { "file": "word-0001.m4a" }` のようにファイルだけを指定する。
- **1 ファイルに複数の語**が入っているなら、`start`・`end`（秒）で区間を指定する。ファイル数が少なくて済む。
  - 区間を鳴らすときは、アプリがファイル全体を読み解く。1 ファイルは長くても数分以内にする（スマホのメモリのため）。
  - AAC（`.m4a`）は、圧縮のときに頭に短い無音が足され、再生する環境によっては音が少し後ろにずれる。ファイルの先頭と区間の間に無音（0.3〜0.4 秒ほど）を入れ、区間の前後に余裕（前 0.05 秒・後ろ 0.15 秒ほど）を取ると安全。
- 形式は、`.m4a`（AAC-LC）か `.mp3` が、どの端末でも鳴らしやすい。HE-AAC は、低いビットレートで声が二重に聞こえるひずみが出ることがある。
- 音声を機械で作るなら、デモ教材の道具（`scripts/demo/make_audio.py`。読み上げのモデル Kokoro と ffmpeg を使う）が参考になる。この道具はデモ教材の形に合わせてあるので、そのままではなく、手直しして使う。

## 6. zip にする

フォルダの中身（`manifest.json`・`items.json`・`audio/`）を zip にする。フォルダごと zip にしてもよい（`my-pack/manifest.json` …）。

- 1 つの zip に入れるパックは 1 つだけ。
- OS が足すファイル（`__MACOSX/`・`.DS_Store` など）は入っていてもかまわない（無視される）。
- 大きさの上限: ファイル数 10,000、合計 200 MB、`manifest.json`・`items.json` はそれぞれ 20 MB まで。音声 1 ファイルは 5 MB まで。

## 7. 取り込む

1. zip をスマホに送る（端末間のファイル共有やクラウドストレージなど）。
2. アプリの「取り込み」の画面で「教材パックを選ぶ」を押し、zip を選ぶ。
3. 誤りがあれば、どの単語のどの項目が違うかが表示される。直して zip を作り直し、もう一度取り込む。

よくある誤り（「画面の表示」は、取り込みの画面に出る文の一部）:

| 画面の表示 | 直し方 |
|---|---|
| UTF-8 として読めませんでした | JSON を UTF-8 で保存し直す |
| manifest.json が見つかりません | zip の直下か、1 段下のフォルダに `manifest.json` を置く（フォルダを 2 段以上重ねて圧縮しない） |
| 品詞の一覧にない値です | 品詞の一覧の言葉に直す（「動詞」ではなく「自動詞」か「他動詞」） |
| audio/ に 〇〇 がありません | `audio/` の中のファイル名と、`items.json` の `file` を合わせる（大文字・小文字も） |
| unit は全ての単語に指定するか、どの単語にも指定しないでください | 全部の単語に `unit` を付けるか、全部から消す |
| units があるのに、単語に unit が指定されていません | 単語に `unit` を付けるか、`manifest.json` の `units` を消す |
| ほかの単語と id が重複しています | 重ならないように振る（既に取り込んだ単語の `id` は変えない） |

## 8. 直して取り込み直す

- 内容を直したら、同じ `id` のまま zip を作り直して取り込む。前の版との違い（追加・削除・内容の変更の語数）が表示される。**削除が思ったより多いときは、単語の `id` を振り直していないかを確かめる**（`id` が変わった単語は、別の単語として扱われ、学習記録が引き継がれない）。
- 学習記録は端末の中にしかない。取り込み直しで学習記録を失わないよう、単語の `id` とパックの `id` は変えない（学習記録のエクスポートは準備中）。スマホでは、ブラウザで開いたままではなく「ホーム画面に追加」して使う（ブラウザが保存したデータを消してしまうことがあるため）。
