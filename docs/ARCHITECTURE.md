# アーキテクチャ設計

画面構成・フォルダ構成・データ構造・実装の順番を定める。
機能の仕様は `docs/specs/`、教材パックの形式は `docs/CONTENT_FORMAT.md` を正とし、この設計はそれを実現する構成を書く。
実装はこの設計に従い、変える場合は先にこのファイルを更新する。

---

## 1. 画面と遷移

画面の切り替えは React Router の HashRouter を使う（URL は `#/packs/...` の形）。配信先のパス構成に依存せず、どの静的ホスティングでも設定なしで動くため。

| URL | 画面 | 内容 |
|---|---|---|
| `#/` | ホーム | 教材パックの一覧（最初に取り込んだ順。テストを促す表示は保留。`study-cards.md` 6 章）と「デモを試す」（`demo-pack.md` 6 章） |
| `#/import` | 取り込み | 教材パック（zip）を選択 → 検証 → 保存 |
| `#/packs/:packId` | ユニット一覧 | 表面の種類の選択肢、ユニットごとの名前・進捗（単語数と学習済みの語数）・前回学習したユニットの印。ユニット学習の開始、テストの範囲選択、復習の開始。「このパックについて」（ライセンス・出典。`demo-pack.md` 6 章） |
| `#/packs/:packId/units/:unitId` | 単語一覧 | ユニット内の単語（並び順）・品詞と訳・定着度（%、未学習なら「未学習」）・音声再生 |
| `#/study` | 学習 | 暗記カードを出題する。条件は URL のクエリで受け取る（下記） |
| `#/settings` | 設定 | ユニット学習の設定（混ぜる単語の数と対象範囲）、表面の表示の設定（例文の音声 → 解説で例文を最初から表示するか）、学習記録のエクスポート / インポート、保存状態、アプリ情報 |

学習画面のクエリ:

| クエリ | 内容 |
|---|---|
| `mode` | `unit`（ユニット学習）/ `test`（テスト）/ `review`（復習） |
| `pack` | 教材パックの ID |
| `units` | ユニット学習のユニット番号（1 つ） |
| `from` / `to` | テストの範囲（開始と終了のユニット番号） |
| `count` | テスト・復習の出題数。`20` / `50` / `100` / `all`。デフォルトはテストが `50`、復習が `all` |
| `unlearned` | テストに未学習の語を含めるか。`1` なら含める（デフォルトは含めない） |
| `face` | 表面の種類（下記） |
| `order` | テストの並び順。`weak`（苦手優先、デフォルト）/ `random` |
| `sessions` | 復習の対象範囲（直前何回の学習か）。1〜20 |

```
ホーム ─┬─ ユニット一覧 ─┬─ 単語一覧
        │               ├─（「学習」ですぐ始める）→ 学習（ユニット学習）
        │               ├─（範囲・出題数などを選ぶ）→ 学習（テスト）
        │               └─（対象範囲・出題数を選ぶ）→ 学習（復習）
        ├─ 取り込み
        └─ 設定
```

- ユニット学習は、ユニット一覧の「学習」を押すとすぐ始める。表面の種類は、ユニット一覧の上に常に出す選択肢で選び、前回選んだものを覚えておく（手順 8 で追加。`study-cards.md` 7 章）。混ぜる単語の数と対象範囲は、設定画面の共通の設定を学習画面が読み込んで使う。
- テストは、ユニット一覧の上の「テスト」ボタンから開くシートで、範囲・出題数・未学習の語を含めるか・並び順を選ぶ（`study-cards.md` 6 章）。
- 復習は、ユニット一覧の上の「復習」ボタンから開くシートで、直前何回の学習を対象にするかと出題数を選ぶ（`study-cards.md` 6 章「復習」）。

|---|---|---|
| 表面の種類 | `Face` | `en`（英語 → 解説）/ `ja`（日本語 → 解説）/ `word-audio`（単語の音声 → 解説）/ `example-audio`（例文の音声 → 解説） |

## 3. フォルダ構成

```
demo/               公開するデモ教材の元のデータ（docs/RULES.md 11 章、docs/specs/demo-pack.md 5 章）。ビルドのときに zip にまとめる
scripts/
├── git-hooks/      コミット前のチェック
├── approve-copyright-review.sh  copyright-reviewer が承認を記録するスクリプト
├── build/          ビルドの処理（デモ教材の zip 化と値の埋め込みをする Vite のプラグイン、配信物の確かめ）
└── demo/           デモ教材の中身を確かめる道具・音声を作る道具（開発のときだけ使う。アプリには含めない）
src/
├── app/            アプリの骨組み（ルーティング、共通レイアウト、起動処理）
├── pages/          画面ごとに 1 フォルダ。その画面専用の部品と CSS も中に置く
│   ├── home/
│   ├── import/
│   ├── units/          ユニット一覧（テスト・復習の条件を選ぶシートを含む）
│   ├── words/          単語一覧
│   ├── study/          学習（カードの表面・裏面、自己申告ボタン）
│   └── settings/
├── components/     複数の画面で使う UI 部品（再生ボタン、解説表示など）
├── features/       機能ごとの処理（画面を持たない）
│   ├── content-pack/   zip 展開・形式の検証・ユニットの自動分割・保存
│   ├── audio/          区間再生（Web Audio API で切り出し、<audio> 要素で再生）と、音声がないときの機械の音声（Web Speech API、端末内の声だけ）
│   ├── cards/          表面の種類ごとに必要なデータの判定、表面の表示名と出せない単語のお知らせの文言、穴埋めの作成
│   ├── session/        出題の組み立て（直前の数回の学習で忘れた単語の判定と、混ぜる単語・復習の単語の選択、テストの並び順、出題数で切る処理）、1 回の学習の出す順と「忘れた」の出し直し、回答の記録の作成、途中でやめた学習の保存値の検証と再開できるかの判定
│   ├── mastery/        定着度の更新
│   ├── backup/         学習記録のエクスポート / インポート
│   ├── demo/           デモ教材の受け取りと取り込み（取り込みは content-pack を使う）、更新の判定
│   └── studyConfig.ts  学習の設定値（study-cards.md 6 章）。どの機能からも読み込んでよい
├── db/             Dexie のテーブル定義とデータ操作
└── lib/            小さな汎用処理（画面で共通に使う React のフックも置く）
```

### 依存の向き

```
app → pages → components
            → features → db
                       → lib
```

- 上から下への一方向だけ import してよい。`lib/` は小さな汎用処理なので、どの層から import してもよい。ただし React のフック（`use〜`）は `features/` からは使わない。逆向き・横向き（`pages/` 同士、`features/` 同士の循環）は禁止。
- `features/` の計算処理（形式の検証、ユニットの自動分割、定着度の計算、出題の組み立て）は **React や DOM に依存させない**純粋な関数にし、Vitest でテストする。
  - 乱数や現在時刻を使う処理は、乱数関数・時刻を引数で受け取れるようにし、テストで固定できるようにする。
- `db/` へのアクセスは `features/` か、`db/` が提供する関数経由で行い、画面から Dexie を直接触らない。
- 教材パックの中身と学習記録の型、2 章の用語の型は `db/types.ts` に置く。端末内に保存するデータの形を表すもので、このファイルは型と定数（例: 表面の種類の一覧）だけを持ち、`components/` を含むどの層から import してもよい。
- ファイル名: React コンポーネントは `PascalCase.tsx`、それ以外は `camelCase.ts`、CSS は `コンポーネント名.module.css`（同じ画面のフォルダで複数の部品が共用する CSS は、用途の名前にしてよい。例: `units/StudySheet.module.css` はテスト・復習のシートの中身と、ユニット一覧の表面の種類の選択肢で共用する）、テストは `対象.test.ts`。

## 4. 端末内データ（IndexedDB / Dexie）

### 教材（教材パックから取り込むもの）

| テーブル | 主キー | 内容 |
|---|---|---|
| `packs` | `id` | `manifest.json` の内容、最初に取り込んだ日時（一覧はこの順。取り込み直しても変えず、並びを保つ）、デモ教材から取り込んだときだけ `demoItemsSha256`（`demo-pack.md` 6 章） |
| `units` | `[packId+id]` | ユニット番号・名前。自動で区切った場合も取り込み時にここへ保存する |
| `items` | `[packId+id]` | `items.json` の各単語、所属ユニット番号、パック内の並び順 |
| `audioFiles` | `[packId+file]` | 音声ファイル本体（Blob） |

### 学習記録

| テーブル | 主キー | 内容 |
|---|---|---|
| `progress` | `[packId+itemId]` | 単語ごとの定着度、最終出題日（いずれかの表面）、表面の種類ごとの最終出題日 |
| `studySessions` | `id`（UUID） | 学習 1 回ごとの回答の生の記録（下記） |
| `reports` | `id`（UUID） | 解説の誤りの報告（日時、パック・単語、`study-cards.md` 10 章） |
| `settings` | `key` | 前回選んだ表面の種類（キーは `face`）、最後にテストした日時と範囲（キーは `lastTest:<packId>`）、最後にユニット学習した日時とユニット（キーは `lastUnitStudy:<packId>`）、ユニット学習の設定（キーは `unitStudy`）、例文の音声 → 解説で例文を最初から表示するか（キーは `exampleTextShown`）、途中でやめた学習の状態（キーは `inProgress:<packId>`。`study-cards.md` 5 章「途中から再開する」）などのアプリの状態 |

#### 回答の記録（`studySessions`）

回答の記録は数万〜10 万件になりうるため、容量を抑えるよう、学習 1 回を 1 件にまとめる。パック・表面の種類・モードは学習 1 回の中で共通なので 1 回だけ持ち、回答ごとの値は回答した順の配列で持つ。1 回答あたり十数バイトで、10 万件でも数 MB に収まる。

| フィールド | 内容 |
|---|---|
| `id` | 学習 1 回ごとの UUID |
| `packId` | パックの ID |
| `startedAt` | 学習を始めた日時（エポックミリ秒） |
| `mode` | `unit` / `test` / `review` |
| `face` | 表面の種類 |
| `itemIds` | 回答した単語の ID（回答した順） |
| `seconds` | 各回答が学習開始から何秒後か（整数） |
| `ratings` | 各回答の自己申告を 1 文字ずつ並べた文字列（`r` 覚えた / `u` 曖昧 / `f` 忘れた） |

- `itemIds`・`seconds`・`ratings` は同じ長さで、同じ位置が 1 つの回答を表す。
- 回答のたびに、この 1 件に追記して上書きする。途中でアプリを閉じても、それまでの回答は残る。

- **教材**と**学習記録**は分けて扱う。エクスポートの対象は学習記録だけで、教材は含めない。
- 教材パックを取り込み直しても、`[packId+itemId]` が同じなら学習記録は引き継がれる。
- 定着度は回答のたびに、今の値と今回の自己申告から更新して `progress` に保存する。`studySessions` は計算し直し（λ や式を変えたとき）と集計のための記録。普段の学習では、ユニット学習に混ぜる単語と復習の単語を選ぶときに、`[packId+startedAt]` の索引でそのパックの記録だけを新しい順に読み、同じパックの復習以外の回が対象範囲の回数分（ユニット学習は設定の値、復習はシートで選んだ値）集まったら止める。その間にある復習の回も読む（`study-cards.md` 6 章）。
- 学習記録の `id` は `randomId()`（`src/lib/random.ts`。UUID v4 の形）で作る。学習記録をインポートするとき、同じ `id` の記録を飛ばすことで重複を防ぐ。
- 「学習済みの単語」は、`progress` に記録がある単語とする。
- テーブル構造を変えるときは Dexie のバージョンを上げる。既存の記録の形を変える・値を作り直す必要があるときは、upgrade で移し替える（索引を足す・消すだけなら不要。IndexedDB が既存の記録から作り直す）。

## 5. 学習の処理の流れ

```
学習開始（mode, pack, face。ユニット学習は units、テストは from, to, count, unlearned, order、復習は sessions, count）
  → 出題する単語を組み立てる（features/session）
      ユニット学習: 選んだユニットの単語 ＋ 直前の数回（設定の対象範囲）の学習で忘れた単語（判定は study-cards.md 6 章）を、設定の数まで。混ぜてランダムに並べる
      テスト: 範囲の単語（未学習の語は含めるときだけ）を、苦手優先またはランダムで並べ、出題数で切る
      復習: 直前の数回（選んだ回数）の学習で忘れた単語を、ランダムに並べ、出題数で切る
      どれも、選んだ表面に必要なデータがない単語は除く（features/cards）
  → カードを 1 枚ずつ出す: 表面 → 裏返す → 自己申告
      「忘れた」カードは、その回の最後にもう一度出す（features/session）
  → 自己申告のたびに studySessions の記録に追記して上書きし、progress の定着度・最終出題日を更新する（features/mastery）
```

- 自己申告のたびの `studySessions` と `progress` と途中の学習（`settings` の `inProgress:<packId>`）の書き込みは、1 つのトランザクションで行う。最初の回答では、前回の学習（`lastUnitStudy` / `lastTest`）も同じトランザクションで書き、書き換える前の値を途中の学習に残す（回答をすべて取り消したときに戻すため）。片方だけが書かれると、定着度と回答の記録と途中の学習が食い違うため。
- 途中の学習には、出題の最初の並び・表面に使う用法・回答ごとの回答する前の学習状況だけを置く。出題の進み具合と申告の回数は、最初の並びに回答の記録を当てはめて求める（記録と二重に持って食い違わないように）。
- 音声（`features/audio`）は、デコード済みのデータを合計の大きさの上限まで覚えておき、同じファイルの別の区間をすぐ再生できるようにする。教材パックを取り込んだら、古い音声が鳴らないように捨てる。
- 定着度の式と設定値は `study-cards.md` 6 章に従う。設定値（ユニットの単語数、混ぜる単語の数、λ など）は、複数の機能で使うため `features/studyConfig.ts` の 1 か所にまとめる。設定画面で変えられる値（混ぜる単語の数と対象範囲）は、そこに初期値と選べる範囲を持ち、選んだ値を `settings` に保存する。

## 6. 実装の順番

薄くても「取り込んで学習できる」一連の流れを先に通し、スマホの実機で確認してから厚くする。

1. ルーティングと共通レイアウト、空の各画面
2. DB のテーブル定義
3. 教材パックの取り込み（展開・検証・ユニットの自動分割・保存）。テスト用に、ダミーの教材パックを生成する関数を用意する
4. ユニット一覧・単語一覧と、区間指定での音声再生
5. ユニット学習（表面は「英語 → 解説」だけ、混ぜる単語なし）と自己申告、学習記録・定着度の保存、解説の誤りの報告ボタン
6. ユニット学習に、直前の数回の学習で忘れた単語を混ぜる処理と、その設定
7. テスト（苦手優先 / ランダム）と、テストを促す表示（テストを促す表示は優先度が低いため保留）
   - 復習（直前の数回の学習で忘れた単語だけの学習）。手順 6 の判定を使う
8. 残りの表面の種類と、ユニット一覧の表面の種類の選択肢。単語の音声 → 解説、日本語 → 解説、例文の音声 → 解説の順に作る（日本語 → 解説は例文中の該当語の扱いを決める必要があり、時間がかかるため後にする）
9. 学習記録のエクスポート / インポートと、解説の誤りの報告の一覧（`study-cards.md` 10 章。一覧を置く画面は未決）
10. デモ教材（`docs/specs/demo-pack.md`）。git フック・`.gitignore`・`biome.json`・copyright-reviewer の更新 → 道具（中身を確かめる・音声を作る）→ デモの中身 → ビルドでの zip 化と配信物の確かめ → 「デモを試す」とパックの情報の表示 → README と配信の設定（`.github/workflows/deploy.yml`）のコメントを直す

- 配信（GitHub Pages、`docs/RULES.md` 3 章）は、実機で確認できるように手順 3 の前に用意する。
- 実装の進み具合は `docs/DEVELOPMENT.md` 3 章にある。

## 7. テスト方針

- `features/` と `db/` の処理は Vitest で単体テストを書く。
- テストデータは自作のダミーだけを使う（`docs/RULES.md` 1 章）。
- 画面の表示や操作は、当面はブラウザと実機で手動確認する。
- 実機での確認は HTTPS で開いて行う。Service Worker・`navigator.storage.persist()` は安全なコンテキスト（HTTPS か localhost）でしか動かないため、LAN の IP アドレスに http で接続すると正しく確認できない。
